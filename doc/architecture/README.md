# Langfuse 架构设计

Langfuse 采用现代化的微服务架构，结合了多种技术栈来构建一个高性能、可扩展的 LLM 工程平台。

## 🏗️ 整体架构

### 架构概览

```
┌─────────────────────────────────────────────────────────────┐
│                    客户端层 (Client Layer)                    │
├─────────────────────────────────────────────────────────────┤
│  Web UI │ Python SDK │ JS/TS SDK │ CLI │ 第三方集成           │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                    API 网关层 (API Gateway)                   │
├─────────────────────────────────────────────────────────────┤
│        Next.js Web Server (前端 + 后端 API)                   │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                   业务逻辑层 (Business Logic)                 │
├─────────────────────────────────────────────────────────────┤
│  tRPC API │ 认证授权 │ 业务规则 │ 数据验证 │ 缓存层           │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                   数据处理层 (Data Processing)                │
├─────────────────────────────────────────────────────────────┤
│  同步处理 │ 异步Worker │ 队列系统 │ 批处理作业                │
└─────────────────────────────────────────────────────────────┘
                               │
┌─────────────────────────────────────────────────────────────┐
│                   数据存储层 (Data Storage)                  │
├─────────────────────────────────────────────────────────────┤
│ PostgreSQL │ ClickHouse │ Redis │ S3/MinIO                  │
└─────────────────────────────────────────────────────────────┘
```

## 📦 技术栈

### 前端技术栈
- **框架**: Next.js 14 (Pages Router)
- **语言**: TypeScript
- **样式**: Tailwind CSS + CSS Variables
- **组件库**: shadcn/ui (基于 Radix UI)
- **状态管理**: TanStack Query (React Query) + tRPC
- **图表**: Recharts
- **构建工具**: Turbo + pnpm

### 后端技术栈
- **Web 服务器**: Next.js API Routes
- **Worker 服务**: Express.js
- **API 协议**: tRPC + RESTful API
- **认证授权**: NextAuth.js
- **数据验证**: Zod v4
- **队列系统**: BullMQ + Redis
- **ORM**: Prisma (PostgreSQL)

### 数据存储
- **主数据库**: PostgreSQL (事务性数据)
- **分析数据库**: ClickHouse (高容量追踪数据)
- **缓存/队列**: Redis/Valkey
- **对象存储**: MinIO/S3 (原始事件、多模态附件)

### 基础设施
- **容器化**: Docker + Docker Compose
- **编排**: Kubernetes (Helm Charts)
- **配置管理**: Terraform (AWS/Azure/GCP)
- **监控**: Prometheus + Grafana
- **日志**: Loki + Grafana
- **追踪**: OpenTelemetry

## 🔄 数据流架构

### 请求处理流程
1. **客户端请求** → Web UI、SDK 或 API 调用
2. **API 网关** → Next.js 服务器处理路由和认证
3. **业务逻辑** → tRPC 处理业务规则和验证
4. **数据处理** → 同步或异步处理数据
5. **数据存储** → 写入相应的数据存储

### 异步处理流程
1. **事件触发** → API 调用或定时任务
2. **队列入队** → Redis 队列存储作业
3. **Worker 处理** → Express.js worker 消费队列
4. **结果存储** → 处理结果写入数据库
5. **状态更新** → 更新处理状态和通知

## 🗄️ 数据库设计

### 双数据库架构
- **PostgreSQL**: OLTP 数据库，处理事务性数据
  - 用户、组织、项目
  - 提示、数据集、评估
  - 配置、权限、审计
- **ClickHouse**: OLAP 数据库，处理分析性数据
  - 追踪、观测、生成
  - 事件、指标、日志
  - 时间序列数据

### 数据模型特点
- **多租户隔离**: 项目级别的数据隔离
- **软删除支持**: 逻辑删除而非物理删除
- **版本控制**: 关键数据的版本历史
- **审计追踪**: 完整的操作审计日志

- **版本控制**: API 版本前缀
- **认证授权**: API Key + 基于角色的访问控制

## 🚀 扩展性设计

### 水平扩展
- **无状态服务**: Web 和 Worker 服务无状态
- **数据库分片**: 支持数据库水平分片
- **缓存分层**: 多级缓存策略
- **队列分区**: 基于主题的队列分区

### 垂直扩展
- **微服务拆分**: 按功能域拆分服务
- **数据库优化**: 读写分离和索引优化
- **异步处理**: 非阻塞异步处理
- **批处理优化**: 批量操作减少开销

## 🔒 安全架构

### 安全层级
1. **网络层安全**: TLS、防火墙、VPC
2. **应用层安全**: 认证、授权、输入验证
3. **数据层安全**: 加密、脱敏、访问控制
4. **运维层安全**: 审计、监控、备份

### 合规特性
- **数据加密**: 传输和存储加密
- **访问日志**: 完整的访问审计
- **数据保留**: 可配置的数据保留策略
- **导出工具**: 数据导出和删除工具

## 📊 监控架构

### 监控体系
- **应用监控**: 性能指标、错误率、延迟
- **基础设施监控**: CPU、内存、磁盘、网络
- **业务监控**: 用户行为、功能使用、业务指标
- **安全监控**: 异常访问、安全事件、合规检查

### 告警系统
- **多级告警**: 警告、错误、严重等级
- **多渠道通知**: 邮件、Slack、Webhook
- **智能降噪**: 告警聚合和降噪
- **自动恢复**: 自动修复脚本和预案
